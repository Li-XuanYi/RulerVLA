## 发现并修复的兼容问题

[Experiment] 首次完整模型测试未通过零 Cue 等价检查：视觉 prefix 约 14.1% 元素超出既定 atol/rtol=0.01，最大绝对差为 2。失败记录保留在 [g1_initial_zero_cue_failure.json](../../outputs/metric_cue_pilot/g1_real_checkpoint/status.json)，没有放宽容差或删掉断言。

[Code/Experiment] 用真实 patch kernel 定位后，普通六通道卷积改变了 CPU 的浮点累加顺序：两有效视角的 stem 最大差约 5.25×10⁻⁶ 和 6.20×10⁻⁶，随后跨过 BF16 舍入边界。这些微小差异在视觉 Transformer 中放大。原始诊断见 [g1_stem_diagnostic.json](../../outputs/metric_cue_pilot/g1_real_checkpoint/stem_diagnostic.json)。

[Code] 新方法的 SigLIP 仍保留一个形状为 [14,14,6,1152] 的 trainable kernel，计算改为 `conv(RGB,W_RGB) + conv(Cue,W_Cue)`，bias 只加一次。RGB 的三通道归约形状与原模型相同，新增切片继续正常参与自动微分。三通道分支与历史冻结 runtime 未改。修正后完整视觉和动作输出均达到本次 CPU 环境中的逐值相同。
